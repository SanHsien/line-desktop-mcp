# LINE Agent MCP

**画像も含めた LINE の文脈。より速く読み、待ち時間を減らします。**

チャットと日付範囲を選択すると、AI アシスタントが会話と利用可能なローカルキャッシュ画像を合わせて、進捗、添付ファイルの文脈、次の対応を整理します。MCP は画像対応モデルにプレビューを渡します。原画像、サムネイル、未取得の状態は明示したままです。

**LINE Agent MCP** は、[bensonmaxai](https://github.com/bensonmaxai/line-desktop-mcp) が保守する Windows 向けコミュニティ版です。[Geoffrey Wang の原著プロジェクト](https://github.com/dtwang/line-desktop-mcp) を基にしています。ローカル MCP クライアントを、サインイン済みの LINE Desktop に接続します。Codex を日常のクライアントとして使えますが、ほかのローカル MCP クライアントも接続できます。本プロジェクトは LINE とは提携していません。

Windows で `LINE_MCP_EXTENSIONS=1` を設定すると、**29 個のツール**を利用できます。設定しない場合は従来の **5 個のツール**が残り、macOS も従来のインターフェースを維持します。

## 1 つの会話で、ひととおりのワークフロー

![読み取り、要約、承認、送信、確認](assets/workflow-ja.svg)

アシスタントに、名前を指定したチャットを確認して現在の進捗を報告するよう依頼します。承認された範囲を読み、必要に応じて別途承認された業務データソースを参照し、アシスタントとの会話に正確な下書きを表示します。宛先と内容を確認した後に送信し、結果を確認します。別のワークベンチは必要ありません。

| 作業 | v2.0.0 で提供するもの |
| --- | --- |
| 業務のフォローアップ | 正確なグループ／個人チャットのローカル履歴、明示的な日付、最大 31 日、ページ送り、スナップショットの鮮度 |
| 添付ファイルの把握 | 必要時に取得するキャッシュ画像プレビュー、小さな PCM WAV ブロック、明示的なメディア可用性 |
| 適切な発言元への返信 | 完全文、送信者、時刻の確認と、1 回だけ使える視覚的なソーストークン |
| 投票の確認 | 承認済みグループにバインドした後、すでに開かれているパネルだけを読み取る |
| クライアント変更への対応 | 検証済みの LINE ビルドハッシュと個別のプロセス状態。未知のビルドではローカル読み取りを拒否 |
| 待ち時間の削減 | 範囲を限定したキー検索、一時的なロケーター再利用、不要な UI 列挙の削減 |

通常のテキスト下書きは Codex で確認します。エージェントは視覚的な UI チェックを実行しますが、実際のメンションや共有コンテンツの変更には、それぞれのワークフローと承認が引き続き必要です。計画があることは、操作が実行済みである証拠にはなりません。

## インストールと v1.2.0 からのアップグレード

新規に別の作業ディレクトリを使う場合は、既存のリポジトリを v2.0.0 タグで取得できます。

```powershell
git clone --branch v2.0.0 --depth 1 https://github.com/bensonmaxai/line-desktop-mcp.git
cd line-desktop-mcp
npm ci --ignore-scripts
```

既存の `line-desktop-mcp` v1.2.0 を更新する場合は、まず現在の MCP クライアント設定をバックアップしてください。その後、既存のチェックアウトを v2.0.0 に更新するか、上の手順で別のソースディレクトリに v2.0.0 を取得します。後者を選んだ場合は、MCP クライアントを新しいディレクトリへ向け直します。LINE アカウントやチャットデータを移行する必要はありません。

Node.js 24 LTS 以降（検証済み: 24.19.0）と、利用するツールに応じて別途構成したランタイムコンポーネントを使用してください。ローカル読み取りには Windows x64、Python x64、`cryptography` と Pillow、固定された SQLite3MC DLL、明示的な `LINE_MCP_PYTHON` / `LINE_MCP_SQLITE3MC_DLL` が必要です。両方の Python パッケージは、メタデータのみのモードを含むすべてのローカル読み取りに必要です。UI ツールは `LINE_MCP_CUA_DRIVER` を使用し、必要に応じて AutoHotkey v2 とローカル Windows OCR を用います。詳細は[インストールガイド](quickstart-windows.md)を参照してください。

再接続してツールスキーマを更新してください。MCP の識別子と既存の 5 個のツールは維持されます。一方で、`stage_line_reply` には完全な `source` と、ソースの観察／確認ツールで得る短期間有効で 1 回限りの `sourceToken` が必要です。旧来のテキストのみの呼び出しは拒否されるため、呼び出し側を更新してください。`get_line_status.localReader` はビルド／プロセスのメタデータを別個に報告し、依存関係や DLL の完全な準備状態は報告しません。[アップグレードとロールバックの詳細](MIGRATING.md)

LINE Agent MCP は、この Windows 向けコミュニティ版の表示名です。v2.0.0 は既存の `line-desktop-mcp` リポジトリとリリース系列を継続するメジャーアップグレードであり、新しい GitHub プロジェクトや別の MCP 名ではありません。

本リリースはローカル stdio のみで動作し、HTTP/REST サーバーや有料クラウドサービスを提供しません。カレントディレクトリの `.env` は自動で読み込まず、MCP クライアントが明示的に渡す環境変数で構成します。

この GitHub タグまたはリリースの `.tgz` を使用してください。本プロジェクトは npm レジストリには公開されず、MCPB バンドルも提供しません。旧い `line-desktop-mcp@latest` パッケージでは本リリースはインストールされません。

## 根拠と制限

![同一マシンでのコールドリーダー比較](assets/performance.svg)

コールドリーダーのコアは **17.866 → 4.661 秒**でした。再起動後の永続的な MCP 接続でのウォーム読み取りは **0.732–0.803 秒**で、クライアント／モデルの追加オーバーヘッドは含みません。これは同一マシンで範囲を限定して観測した値であり、すべての環境での性能保証ではありません。

この 17.866 → 4.661 秒は、範囲を限定した**テキスト履歴**の Python コア計測で、画像プレビューのデコード、モデル、GUI のオーバーヘッドは含みません。画像理解を含むエンドツーエンドの待ち時間ではありません。ビルドゲートはコールド比較後に統合され、個別チェックは約 24 ms でした。ウォームの 0.732–0.803 秒にはビルドゲートが含まれます。

実際の LINE の再起動と読み取りを 2 回確認し、実際の画像転送も独立してデコードしました。これらは同一マシンで範囲を限定して得た確認結果であり、普遍的な性能保証ではありません。

- ライブ GUI の根拠は、Windows の LINE **26.4.2.3957、繁体字中国語 UI**、CUA Driver 0.23.2 を対象にしています。文書を翻訳しても、ほかの UI 言語を認証したことにはなりません。
- クエリ日付と投票計画では **Asia/Taipei、UTC+08:00** を使用します。
- ローカル読み取りは、ログイン中の LINE プロセスメモリに対する範囲を限定した読み取り専用アクセスを使います。アクセスを拒否された場合またはビルドが未検証の場合は停止します。
- ローカルキャッシュの記録は完全なサーバーアーカイブではありません。対応するプレビューは PNG/JPEG、GIF/WebP の先頭フレーム、小さな PCM WAV です。ほかの認識済みメディアはメタデータを返します。一般的な再生や文字起こし機能を意味するものではありません。
- ローカルキャッシュに画像がないことは、AI の処理がオフラインであることを意味しません。MCP が画像対応モデルへ渡せるのは、利用可能なキャッシュプレビューだけです。
- テキストが存在しても、相手への到達や既読状態は証明されません。実際のメンショントークンには視覚的な確認が必要で、不確実な送信は自動で再試行しません。
- デコードと OCR はローカルで実行されます。返された内容は、選択した AI クライアントのデータ処理ポリシーに従います。

合成検証には、構成済みの Python で `npm test` と `npm run test:python` を実行してください。[詳細なツール仕様と検証](windows-extensions.md)
