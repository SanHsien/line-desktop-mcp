# v3.0.0 — ตรวจสอบแชตก่อนดำเนินการ

[ทุกภาษา](README.md) · [ดาวน์โหลด](https://github.com/bensonmaxai/line-desktop-mcp/releases/tag/v3.0.0) · [การติดตั้ง](../quickstart-windows.md) · [การย้ายและย้อนกลับ](../MIGRATING.md#upgrading-to-v300)

![LINE Agent MCP](../assets/line-agent-cover-v3.png)

รีลีสความปลอดภัยนี้ทำให้ขอบเขตของแชตเข้มงวดขึ้นสำหรับการอ่าน ร่าง และส่งผ่าน GUI และจำกัดสื่อที่ส่งกลับ ชื่อ MCP ยังคงเป็น `line-desktop-mcp` บน Windows สามารถใช้ 29 tools แบบ opt-in ด้วย `LINE_MCP_EXTENSIONS=1` หรือคง 5 tools ค่าเริ่มต้นเป็น descriptors ไว้เมื่อไม่ตั้งค่า ชื่อ ลำดับ และ input schema ของทั้ง 5 tools ไม่เปลี่ยน แต่คำอธิบายจะแสดงความพร้อมใช้ตามแพลตฟอร์ม นี่จึงเป็น major version เพราะ prerequisites ของ Windows GUI และการรองรับ macOS เปลี่ยนไป

## การเปลี่ยนแปลงด้านความเข้ากันได้และขอบเขต

- ทุกเส้นทาง GUI บน Windows สำหรับแชตที่ระบุชื่อ รวมทั้ง 5 tools ค่าเริ่มต้น ต้องใช้ CUA, `LINE_MCP_PYTHON` / `LINE_MCP_SQLITE3MC_DLL` ที่ระบุชัดเจน, SQLite3MC DLL ที่ตรึงไว้ และ Python `cryptography` กับ Pillow สถานะหรือรายการความสามารถอย่างเดียวไม่ได้ยืนยันว่าองค์ประกอบเหล่านี้พร้อมใช้
- snapshot metadata-only แบบส่วนตัวจะตรวจชุดที่มีขอบเขตของกลุ่มและ direct chat เดิมก่อนแตะ LINE window และไม่อ่านข้อความหรือสื่อ ชื่อที่แสดงแบบดิบต้องตรงทุกตัวอักษร กรณี NFC เทียบเท่า การยุบ/ตัดช่องว่าง รูปแบบชนกันจากจำนวนสมาชิก รายการไม่ครบ หรือการชนข้ามชนิดแชต จะปฏิเสธแบบ fail closed
- ให้เปิดแชตเป้าหมายก่อนด้วยผู้ใช้หรือเวิร์กโฟลว์ UI แบบมีผู้ใช้กำกับที่ตรวจสอบแยกต่างหาก `open_line_chat` ตรวจสอบเฉพาะแชตที่เปิดอยู่แล้วและไม่เลือกผลการค้นหารายการแรก ยังคงต้องยืนยันส่วนหัวใหม่หลังจากระบุตัวตนในเครื่อง
- macOS ยังแสดง 5 tools ค่าเริ่มต้น แต่การอ่านประวัติแชต การส่ง และไฟล์จะคืน `LINE_CHAT_VERIFICATION_UNAVAILABLE` ก่อน automation รีลีสนี้ไม่มีตัวตรวจสอบแชตหรือการรองรับการใช้งานจริงบน macOS

## การแก้ไขด้านความปลอดภัย

- source สำหรับการตอบกลับและภาพ fallback หลัง Reply จะคืนเฉพาะบริเวณข้อความของแชตที่ยืนยันแล้ว มีการตรวจขอบเขต crop ขนาด PNG และ fingerprint พิกัดที่เปิดเผยเริ่มจากจุดกำเนิดของภาพที่ถูกครอบ และ bridge จะ rebase ภายในเพียงครั้งเดียว
- ส่วนหัวใหม่, chat reference, ชนิดกลุ่ม/direct และพิกเซลที่สังเกตจะผูกกับ confirmation token หาก guard ก่อนหรือหลัง GUI พบ drift จะปฏิเสธหรือคืนสถานะไม่แน่ชัดพร้อม `operationMayHaveCompleted:true` แม้ได้ลองดำเนินการแล้ว โดยไม่ส่งซ้ำอัตโนมัติ
- การคัดลอกประวัติผ่าน GUI จะเก็บรูปแบบ clipboard เดิมที่ใช้ได้ ตรวจ owner และ sequence ของ LINE แล้วคืนค่าก่อนส่งผล เมื่อมีผู้เขียนใหม่จะเก็บข้อมูลนั้นไว้และปฏิเสธการอ่าน Clipboard History, listener ภายนอก และ race ขนาดเล็กระหว่างเปรียบเทียบ/คืนค่ายังอยู่นอกขอบเขตการรับประกันนี้
- APNG คืนเฉพาะเฟรมแรก ส่วน source ของ PNG/JPEG แบบ static ไม่เปลี่ยน metadata JSON ที่ลึกเกินจะกลายเป็น unknown โดยไม่หยุดแถวปกติข้างเคียง การอ่าน local DB และ metadata ของโพลเดิมยังคงพฤติกรรมเดิม

## การตรวจสอบและข้อจำกัด

รีลีสนี้ผ่าน synthetic regression tests ของ Node/Python, pinned SQLite3MC engine และ native AutoHotkey syntax parsing ผลสุดท้ายคือ Node tests ผ่าน 221 รายการ, Python tests ผ่าน 101 จาก 102 รายการ และ skip 1 รายการเพราะ symlink ของ Windows filesystem การทดสอบครอบคลุมชื่อกำกวม token หมดอายุ clipboard guards crop failures APNG และ JSON ลึก

v3.0.0 ไม่ได้รันการอ่านแชต LINE จริง การใช้ clipboard จริง การส่งจริง หรือ GUI end-to-end ค่า 17.866→4.661 วินาทีสำหรับ text-history core, 0.732–0.803 วินาทีสำหรับ warm read และการอ่านบนเครื่องจริงของ v2.0.0 เป็นหลักฐานเดิม ไม่ใช่ benchmark ของ GUI guards ใหม่ การระบุตัวตนในเครื่องและพิกเซล UI ไม่ใช่การผูก DB ID แบบ atomic จึงยังมีความเสี่ยงจากการเปลี่ยนพร้อมกันระหว่างการสังเกต

## การติดตั้งและย้อนกลับ

ใช้ source tag `v3.0.0` บน GitHub หรือไฟล์แนบ `line-desktop-mcp-3.0.0.tgz` กับ `SHA256SUMS.txt` ไม่มีการเผยแพร่ผ่าน npm registry หรือ MCPB แตกไฟล์ลงไดเรกทอรีภายในเครื่องใหม่ แล้วรัน `npm ci --ignore-scripts` ตั้งค่า Node.js 24 ขึ้นไป, CUA, Python, SQLite3MC DLL และ AutoHotkey v2 หากเส้นทาง GUI ต้องใช้ เชื่อม MCP client ใหม่และรีเฟรช schema เก็บแพ็กเกจและ launcher เดิมไว้สำหรับ rollback โดยไม่ต้องย้ายบัญชี LINE หรือข้อมูลแชต [ข้อกำหนดฉบับเต็ม](../windows-extensions.md)
